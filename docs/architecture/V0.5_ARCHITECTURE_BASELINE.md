# v0.5 Architecture Baseline — Open Source First

Status: **FROZEN FOR IMPLEMENTATION**
Branch: `v0.5-open-source-first`
Previous baseline: `release/v0.4-governed-runtime`

## Goal

Turn the template from a mostly custom platform runtime into a governed assembly of mature open-source components, while preserving our architecture, security, source-authority and acceptance rules.

## Responsibilities

### Forge owns

- visual agent builder
- visual workflow builder
- LangGraph runtime integration
- tool registry and tool sets
- inbound and outbound MCP
- REST/GraphQL/SQL/code tools
- knowledge ingestion and RAG
- curated Q&A
- long-term agent memory
- human-in-the-loop pauses/handoffs
- auth, project RBAC and API keys
- secrets references
- triggers/schedules
- tracing/token/cost spans
- evaluations
- audit/version history
- API/MCP/web-widget delivery surfaces

### LiteLLM OSS core owns

- provider abstraction
- model routing
- provider failover/routing policy when configured
- Groq integration
- OpenRouter integration
- stable OpenAI-compatible gateway presented to Forge

Only the MIT-licensed surface outside LiteLLM's `enterprise/` directory is part of this baseline.

### This template owns

- governance and ADR policy
- source-authority rules
- OSS adoption policy
- security acceptance rules
- model-routing policy
- domain-pack contract
- business-tool authorization contract
- production-readiness gates
- upgrade/pinning strategy
- real E2E acceptance evidence

### Consuming products own

- business rules
- business persistence
- product-specific UX
- authoritative business APIs
- product permissions
- domain evaluation datasets
- source ranking/reconciliation rules

## Decisions

### D1 — No platform rewrite

Do not port Forge features into custom local equivalents. Use Forge extension/configuration points first.

### D2 — Upstream source stays upstream

Forge and LiteLLM are pinned in `upstream/UPSTREAM_COMPONENTS.lock.json` and bootstrapped into `vendor/`, which is gitignored. We do not vendor-copy their source into this repo.

### D3 — No duplicate memory layer initially

Forge long-term memory is the default. Mem0 is not part of v0.5 unless a measured product requirement proves a gap.

### D4 — No duplicate observability stack initially

Forge traces/evaluations are primary. OpenTelemetry export may feed Langfuse or another collector later without replacing Forge's run trace.

### D5 — No duplicate workflow UI

Forge's React Flow canvas is the default workflow builder. Product UIs may be custom but must not reimplement a generic canvas without an ADR.

### D6 — Model providers are behind a router

Agents must not hard-code Groq, OpenRouter, OpenAI, Anthropic or local model endpoints. Provider choice belongs to the router/runtime configuration.

### D7 — Groq + OpenRouter are the first external routes

The initial routing target is:

- Groq: fast/low-latency route
- OpenRouter: broad model-access/general route

Concrete models are runtime configuration and are not frozen in architecture.

### D8 — Business writes remain governed

An agent may reason freely but must not bypass product authorization, persistence or approval requirements. External tools exposed to Forge must preserve the consuming product's authorization and audit boundaries.

### D9 — Business data remains authoritative outside memory

Memory is contextual assistance, never source of truth for financial values, inventory, orders, infrastructure state, migration status, compliance status or other live business facts.

### D10 — Connectors are reuse-first

Use an existing maintained MCP/REST connector when acceptable. Forge's own README states its one-click connector marketplace is not yet fully shipped; until then, integrations use proven MCP servers or governed REST/GraphQL tools rather than custom connector frameworks.

## Deployment profiles

### Local validation

Forge local/Docker stack, offline `fake:echo` model first. No external model key is needed to validate UI, workflows, MCP and governance plumbing.

### Routed model validation

Forge -> LiteLLM -> Groq/OpenRouter. This gate must prove streaming, tool calling, errors, timeout handling and trace/cost visibility with real provider calls.

### Product integration

Product UI/API -> Forge run API or MCP surface -> governed product tools -> authoritative product systems.

## Acceptance gates for v0.5

1. Pinned upstream checkout reproducible.
2. Forge UI boots from pinned commit.
3. Forge API healthy.
4. Offline agent run passes.
5. Visual workflow saves and reopens.
6. MCP list/call path passes.
7. HITL pause/resume passes.
8. Persistence survives restart in the selected deployment profile.
9. LiteLLM router boots from pinned release.
10. Groq real call passes through router.
11. OpenRouter real call passes through router.
12. Forge can call the router through the agreed OpenAI-compatible boundary.
13. Trace shows model/tool activity and failures clearly.
14. One reference domain tool is integrated without bypassing authorization.
15. No duplicate custom subsystem was introduced without an approved ADR.

v0.5 is not production-ready until all applicable gates above have evidence.
