# v0.5 Freeze Readiness Checklist

Version candidate: `0.5.0-open-source-first`
Branch: `v0.5-open-source-first`
Release state: **NOT FROZEN / NOT MERGED / NOT PRODUCTION**

This checklist is the release gate for the Open Source First foundation. A green unit test alone is not enough.

## A. Architecture and source authority — MUST PASS

- [x] v0.4 preserved on `release/v0.4-governed-runtime`.
- [x] Forge selected as the platform foundation by explicit architecture decision.
- [x] Forge pinned to an immutable commit and license verified.
- [x] LiteLLM pinned to a specific release/commit.
- [x] Official GitHub MCP pinned to release/commit/container digest.
- [x] No replacement Chat UI, workflow builder, agent engine, MCP framework, memory layer, auth layer, or tracing platform is custom-built where Forge already provides the capability.
- [x] Model provider choice remains runtime configuration, not an architecture dependency.

## B. Core runtime — MUST PASS

- [x] Forge high-value backend acceptance suite.
- [x] Forge frontend tests.
- [x] Forge production frontend build.
- [x] Forge authenticated login.
- [x] Project persistence/reopen.
- [x] Workflow persistence/reopen.
- [x] Live deterministic agent execution.
- [x] Same-thread continuation.
- [x] Browser owner-console smoke.
- [x] LiteLLM router boots from pinned image.
- [x] Groq route catalog loads.
- [x] OpenRouter route catalog loads.

## C. External tool integration — MUST PASS

- [x] Official GitHub MCP runs through Forge native MCP path.
- [x] Connector is read-only for the reference acceptance path.
- [x] Tool allowlist is bounded.
- [x] Real GitHub data is returned through the MCP adapter.
- [x] Credential is excluded from Git and evidence artifacts.
- [x] Forge agent workflow can attach the MCP server natively.

## D. Stabilization / failure paths — MUST PASS BEFORE FREEZE

- [ ] Python dependency resolution snapshot captured from the accepted environment.
- [ ] `pip check` passes on the accepted Python graph.
- [ ] Frontend install passes with `pnpm --frozen-lockfile` and does not mutate the lockfile.
- [ ] Error-workflow behavior passes.
- [ ] Tool-reliability behavior passes.
- [ ] Rate-limit behavior passes.
- [ ] Trace/interrupt behavior passes.
- [ ] Security-hardening / SSRF behavior passes.
- [ ] HITL service/runtime failure paths pass.
- [ ] Router rejects an invalid master key.
- [ ] Router fails closed for an unknown model route.
- [ ] No provider secret value is embedded in tracked config.

Evidence source: `.github/workflows/v05-stabilization.yml`.

## E. Live provider / autonomous tool loop — REQUIRED BEFORE MERGE, CREDENTIAL-BLOCKED

- [ ] `GROQ_API_KEY` from the existing Saudi Business Groq account is added to the approved secret store for this project.
- [ ] Forge -> LiteLLM -> Groq returns a real model response.
- [ ] Live model autonomously selects the bounded GitHub MCP tool.
- [ ] Real GitHub tool output returns to the model.
- [ ] Model produces a final answer based on the real tool result.
- [ ] Trace/evidence shows model call + MCP tool call + final response in one run.

Known blocker: the Groq secret exists in Saudi Business but has not yet been wired into this project. Owner plans to wire it later. Do not re-design around this temporary credential blocker.

OpenRouter live inference/fallback remains a separate gate if/when an authorized `OPENROUTER_API_KEY` is provided.

## F. User-visible HITL — REQUIRED BEFORE MERGE

- [ ] A real workflow reaches `human_input` and visibly pauses.
- [ ] Approve resumes the same run/thread and reaches the expected next state.
- [ ] Reject follows the bounded reject path.
- [ ] Refresh/reopen preserves the pending/terminal state.
- [ ] Duplicate/late approval cannot double-execute the action.

Unit/service HITL tests do not alone close this gate.

## G. Release hygiene — MUST PASS BEFORE FREEZE

- [ ] All required v0.5 CI gates are green on the final freeze candidate SHA.
- [ ] `main` remains unchanged until explicit merge approval.
- [ ] PR #1 remains Draft until all required merge gates pass or an explicit waiver is recorded.
- [ ] No API keys/tokens are present in Git diff, logs committed to Git, or release documentation.
- [ ] Final `V05_STATUS.md` lists exact run IDs and unresolved items.
- [ ] Clean compare against v0.4 reviewed for architecture-scope drift.
- [ ] Freeze tag created only after explicit release approval.

## Release decision semantics

- **PASS** = directly evidenced by an accepted runtime/test artifact.
- **BLOCKED** = prerequisite unavailable (for example an authorized provider credential); not treated as PASS or FAIL.
- **FAIL** = exercised and did not meet acceptance criteria.
- **DEFERRED** = explicitly scheduled after the current gate and documented with a resume point.

No item may be silently converted from MUST PASS to optional. Any waiver requires an explicit architecture/release decision recorded in the repository.
